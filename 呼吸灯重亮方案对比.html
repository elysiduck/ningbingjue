凝冰结魄 · 呼吸灯重新点亮 · 方案对比

呼吸灯「完全没了」但「不卡了」—— 根因是 2026-08-29 重构漏掉了两个顶层辉光窗口的 show()。下面是几种呼吸范围/强度的可视化对比，挑一个我来实现。

✓ 根因已定位 · 修复核心是补 2 行 show() · 各方案共享同一套「缓存位图 + DWM alpha」渲染架构

① 根因（已查证）

两个辉光层 `_GlowOverlay`（呼吸辉光）与 `_GlowBorderOverlay`（霓虹边框）被创建为带 Qt.Window 标志的独立顶层窗口，但只调了 setGeometry + raise_()，从未调用 .show()。raise_() 不会让隐藏的顶层窗口可见。

self._glow_overlay = _GlowOverlay(self)
self._glow_overlay.setGeometry(self.rect())
self._glow_overlay.raise_()
# 缺 self._glow_overlay.show()
self._glow_border = _GlowBorderOverlay(self)
self._glow_border.setGeometry(self.rect())
self._glow_border.raise_()
# 缺 self._glow_border.show()

证据链：① 全文件检索 _glow_overlay.show / hide / setVisible 结果为 0 处；② 备份 src_ui_backup_20260825_1500 用的是「主窗 setWindowOpacity」旧方案、根本没有这两个 overlay，说明它们是 0829 新增且从未接通过显示；③ 与症状互为正反：层不可见 → 呼吸没了；层不参与合成 → 不卡了。

② 实时预览（下面都是按 ~2.36s 真实呼吸周期在动）

方案 A · 全窗径向呼吸

整窗（含卡片区）随呼吸明暗 · 观感最沉浸
以窗口中心为圆心的径向渐变：中心微光 → 边缘高亮。整块 HUD（含托盘卡片区）一起柔和地亮灭，是最接近「真正的呼吸灯」的形态。
grill：性能已靠 0829 的「缓存位图 + setWindowOpacity」架构解决——每帧只是一次 blit + DWM alpha 乘法，卡片零重绘。唯一保留风险：分数 DPR（掌机 1.5×）下透明顶层窗口的 alpha 合成有恒定开销，但远小于旧方案的整窗 paintEvent。掌机若仍有感，降级到 C 即可。

方案 B · 边缘均匀衰减呼吸

四边恒亮呼吸 · 中心较平静
辉光只在靠近四边处提亮并随呼吸脉动，中心保留一层很淡的底光。比 A 收敛一点，边缘「呼吸边框」的感觉更强，中间不刺眼。
grill：实现上 = 把 A 的径向渐变中心挖空（透明）。渲染成本与 A 完全相同（同一 overlay + alpha）。属于「视觉偏好」差异，不是性能取舍。

方案 C · 边框呼吸 + 静态中心底光

仅霓虹边框脉动 · 中心恒亮不闪 · 最稳
呼吸只发生在霓虹边框（box-shadow 脉动），托盘中心是一层一次性烘焙、不随呼吸变化的静态冰蓝底光——中间不再是纯黑，但也不会闪。最克制、最稳。
grill：唯一需要改渲染内容（中心辉光走稳态层、不进呼吸层）。性能最无忧，是掌机上的「安全牌」。代价：沉浸感弱于 A/B，中间是「静」的。

方案 D · 整窗透明度呼吸

整窗 opacity 脉动 · 文字也跟着闪
直接对主窗口 setWindowOpacity 做正弦脉动。代码最简单，但文字和卡片会一起变暗变亮，可读性随呼吸起伏，像整个 App 在闪。
grill：不推荐。它把「内容」也卷进脉动，掌机上文字本就因分数 DPR 发糊，再叠透明度起伏会更糊。除非你就是要「整块忽明忽暗」的极简风，否则别选。

我的推荐：方案 A（全窗径向呼吸）+ 补 show()。
理由：0829 重构已经把「会卡」的整窗 paintEvent 换成了「缓存位图 + DWM alpha」的安全架构，A 的渲染成本其实和原来一样低；补两行 show() 就能把原设计意图完整拿回来，沉浸感最好。
安全网：如果你主要在 1080p@150% 掌机上用、担心分数 DPR 的透明合成开销，选 C 作为零风险兜底——视觉上仍有「边框在呼吸 + 中心不黑」，且完全不碰卡片区。
