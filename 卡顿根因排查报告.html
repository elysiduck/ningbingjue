排查日期 2026-08-29 · 源码运行（launch.bat）· 症状：HUD 界面反应迟钝、开机即卡、关闭呼吸灯仍卡、空闲桌面也卡
结论（代码层）

对空闲稳态（不开游戏、关闭呼吸灯、仅 HUD 自身在桌面）逐路径静态审查后， 默认配置下代码路径是干净的：没有持续重绘、没有 UI 线程阻塞的子进程、 后台负载极低（仅 1 个 1Hz 的 Get-Counter 宿主）。前两次“呼吸灯修复”针对的是真实存在但 非主导的开销，因此没解决你的卡顿。

你的卡顿只剩两类现实可能：
① 你手动开启了「GPU 浮动锁频」或「负载门控降压」 —— 二者都会每秒调用 ryzenadj.exe， 而你的机器 Core Isolation（内核隔离/内存完整性）是开启的，驱动加载被拦，ryzenadj 会失败甚至挂起/空转， 占满一个 CPU 核或持有全局单实例互斥，造成全系统/UI 卡顿。
② 你机器的运行时特有问题（驱动/DPI/PowerShell 行为），需靠下面的取证工具确认。

二、最可能的真实原因：ryzenadj 在 Core Isolation 机器上挂起/空转

高概率（若相关开关已开启）

你的历史诊断已确认：Windows Core Isolation（内存完整性）开启，拦截了 ryzenadj 依赖的 WinRing0x64.sys 驱动加载。 在此环境下 ryzenadj.exe 会失败退出，极端情况下进程挂起不退出（需 10s 超时 taskkill）或空转占用一个核心。

  • GPU 浮动锁频（GPU auto-lock）：独立 daemon 线程每 1.5s 跑一次决策，开启时调用 ryzenadj --gfx-clk。 默认 gpu_float_enabled=False（config.py:190），除非你手动开过。
  • 负载门控降压（undervolt）：_uv_tick 在 UI 线程每 1s 跑；状态机仅在“档位变化”时写 ryzenadj。 默认 enabled=False（undervolt.py:131），空闲无游戏→状态恒为“无游戏 CO=0”→不会写。

若二者任一开启，且 ryzenadj 在你的机器上挂起：要么占满一个核（全系统卡），要么长期持有 _RYZENADJ_BUSY 全局互斥，使其它 ryzenadj 调用被跳过/排队，表现为“HUD 反应迟钝、开机即卡、空闲也卡”。 这完全符合你三次描述的症状，且前两次修复都碰不到它（因为根本不是渲染问题）。

三、立即 A/B 验证（无需取证工具，10 秒）

  1. 打开凝冰结魄，进「电源」卡片，看 GPU 浮动锁频 是不是 ON；进降压相关卡片，看 负载门控降压 是不是 ON。
  2. 把这两个开关都关掉（若开着）。
  3. 观察 30 秒：卡顿是否立刻消失？

→ 若消失：坐实是 ryzenadj 挂起。根因是 Core Isolation 拦驱动，与代码无关； 后续我可加一道“检测到 Core Isolation 就直接禁用 ryzenadj 类功能并弹一次提示”的防护（低风险）。

→ 若仍卡：排除 ryzenadj 假设，进入第④步用取证工具拿真凭实据。
