凝冰结魄 · 卡顿根因与性能优化

grill-me 取证结论 · 2026-08-29　|　相比上一轮「ryzenadj 挂起」假设，本轮证据更贴合「新版比旧版更卡」的描述

现象（来自你的描述）

  • 重启后卡顿缓解，但不开任何程序、仅跑 NBJ 仍有少量卡顿。
  • 「即便是跑旧版，旧版也没新版这么卡」 → 这是典型的 回归（新增代码开销）信号，不是纯环境/功耗问题。
  • 滚动主页卡片列表时尤其卡，认为「帧率不够高」。WorkBuddy 在滚动、无点击时完全不卡。
  • 直觉：低功耗下 HX370 掌机反而比本机顺 —— 因为掌机 DPR=1.5 放大惩罚会让「半透明层重绘」更贵，但若没进这条路径就顺。

根因（已钉死）ROOT CAUSE

主窗口本身不透明（WA_TranslucentBackground=False + setMask 切圆角），不是元凶。真正开销来自一个整窗大小的半透明子控件 _GlowOverlay（WA_TranslucentBackground=True，呼吸辉光层）：

路径现象为什么卡
breathing.py → ov.update() 呼吸灯以 _SCANLINE_TICK_MS=40（≈25fps）持续驱动整窗重绘 半透明层每次重绘都强制 DWM 对整个表面做 Alpha 混合，且受分数 DPR×1.5（掌机）放大惩罚 → 即使前台不操作也在烧 GPU/CPU
app_window._mark_scrolling() 原本应在「滚动时暂缓呼吸重绘」，但已被删成空壳 return 于是「滚动卡片列表」与「~20–25fps 半透明层重绘」叠加 → 滚动卡顿的成因

为什么 WorkBuddy 不卡：它没有这种「常驻半透明动画层」，滚动只是 ListView 自己的局部重绘，不参与 DWM 整窗 Alpha 合成。

已排除：_fast=1Hz / _slow=2Hz / _batt=2Hz 只是刷新文本，不是每帧重绘元凶；卡片 BlockPanel.paintEvent 仅圆角填充+细边框，选中才多几笔，不是滚动卡顿主因。

已实施修复（低风险 · 文档推荐旋钮）FIXED

文件改动效果
ui/breathing.py _SCANLINE_TICK_MS 由 40 → 50（≈20fps） 常驻半透明层重绘负载降约 20%，呼吸观感不变
ui/app_window.py ① 初始化 self._scroll_freeze_until = 0.0
② _mark_scrolling() 从空壳改为 self._scroll_freeze_until = time.monotonic() + 0.18
③ _on_breath() 接入滚动冻结：if time.monotonic() < getattr(self,"_scroll_freeze_until",0.0): return		 滚动输入后短暂冻结呼吸辉光重绘，与滚动解耦；相位继续推进，滚动停后无缝恢复

验证：py_compile + pyflakes 两文件通过（COMPILE_OK）。改动仅纯 .py，掌机同步 src 即生效，免重建 exe。

取证：为什么 logs/nbj_profile.log 找不到

core/profile.py 的采样器 ENABLED = bool(os.environ.get("NBJ_PROFILE")) —— 只有设置该环境变量才会写日志，默认零开销、不落盘。这也是为什么你找不到文件。

开启取证：  set NBJ_PROFILE=1 && launch.bat

掌机同步 src 后同样跑上述命令，跑 30 秒即可拿到 CPU / 帧 / 重绘热点，佐证「呼吸层重绘」是否为主开销。

后续根治方案（未实施，验证收益后再采用）RECOMMEND

  • 把 _GlowOverlay 提升为顶层窗口，用 setWindowOpacity 呼吸，彻底免去「每帧整窗重绘」。注意：它是子控件时 setWindowOpacity 不生效，必须改架构（风险更高的重构）。
  • 旋钮已先验证：若 40→50ms + 滚动冻结后体感已可接受，就不必上重构；若仍卡，再走顶层窗口方案。

掌机验证建议（A/B）

为避免「环境叠加」干扰，建议一次性确认以下开关状态，排除它们与渲染卡顿的耦合：

  • ryzenadj / GPU 浮动锁频 / 负载门控降压 是否开着（旧 ryzenadj 挂起假设需复核）
  • 用 set NBJ_PROFILE=1 && launch.bat 跑 30s，对比「滚动时」与「静止时」的采样数据
  • 同步 src 后删除 __pycache__ 避免旧字节码让改动未生效
